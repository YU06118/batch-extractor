## 2. 核心架构：两阶段 staging → relocate

1. `stage_archive()`：把压缩包逐条目解到 `tempfile.TemporaryDirectory()` 隔离暂存区。
2. `relocate()`：遍历暂存区，按原始相对路径搬到 `输出目录/<包名>/<相对路径>`。

**为什么这样设计**：所有格式（zip / tar / 单文件流 / 7z）都走同一套冲突检测、覆盖策略、路径安全与统计逻辑；外部工具失败时暂存区的半成品不会污染输出目录。代价是双倍磁盘 IO 与临时空间。

## 3. 输入 / 输出约定

- 输入二选一或叠加：`mode=dir`（递归扫描输入目录）、`mode=files`（一行一个路径，目录项自动展开）。输出目录若位于输入目录内会被自动排除，避免把上次结果反复当输入。
- 默认 `overwrite=false`：目标已存在 → 跳过并记 `skipped/conflict`（记录冲突绝对路径）。
- 默认 `useArchiveSubdir=true`：输出为 `输出目录/<包名>/<包内原始相对路径>`，完整保留目录层级、空目录与中文名；关闭后直接铺到输出目录，跨包同名会计入 conflict。
- `.gz/.bz2/.xz/.lzma` 属单文件流压缩，无内部层级，输出为去掉压缩后缀的文件名。
- `.7z/.rar` 依赖 7-Zip，自动探测顺序为：显式路径 > PATH > **Windows 卸载注册表 `InstallLocation`** > 常见安装位置；也可显式指定 `--7z`。无工具时明确归类 `unsupported`。
- 无扩展名文件按文件头魔数识别（PK、1f8b、7zBC AF 27 1C、Rar!、BZh、FD 37 7A 58 5A、ustar）。

### 分卷压缩包（.001 / .002 …，如用户实际要解的 `7z.001`）

- **识别**：`NUM_VOLUME_RE = ^(.+)\.(\d{3,4})$`（`7z.001`、`xxx.7z.001`），以及 `PART_VOLUME_RE = ^(.+)\.part(\d+)\.rar$`。`detect_format()` 在扩展名匹配之前先判分卷，一律返回 `external`。
- **归组 key**：`(normcase(父目录绝对路径), normcase(组名), 命名风格, 编号宽度)`。用 `os.path.normcase` 兼顾 Windows 大小写不敏感 / Linux 大小写敏感；`partN.rar` 的宽度固定记 0，否则 `part9` 与 `part10` 会被误拆两组。
- **自动补全**：`scan_volume_group()` 扫描首卷所在目录，把同 key 的所有卷找齐。因此目录模式、只填首卷、只填末卷、把全部卷都填上，四种输入结果完全一致且自动去重。
- **只解首卷**：把 `.001` 交给 `7z x`，7-Zip 自动串读同目录 `.002/.003…`（实测 `7z.001`~`7z.005` 重命名后仍可正常打开）。Python 内置库无法拼接分卷。
- **完整性预检**：编号须为 `1..max` 连续；缺首卷或中间断号 → `failed(missing_volume)`，整组跳过并列出缺失文件名，不影响其它包。
- **输出子目录名取组名**：`7z.001 → 7z`、`xxx.7z.001 → xxx`、`xxx.part1.rar → xxx`，不是首卷文件名。
- 7z 子进程必须 `stdin=subprocess.DEVNULL`：缺卷时 7-Zip 可能交互式询问「下一卷路径」，否则任务会卡死；加密包无密码时同样会尝试交互，表现为 `Break signaled` / rc=255。

### 加密压缩包（密码 / 候选密码 / 密码本）

- **三种输入可叠加、去重保序**：`password`（单密码）、`passwords[]`（候选列表，页面一行一个）、`passwordFile`（UTF-8 密码本，一行一个，空行忽略）；另有环境变量 `BX_PASSWORD` / `BX_PASSWORD_FILE`，避免密码进入命令行进程列表。上限 `MAX_PASSWORDS=200`。
- **尝试策略**：每个包先试「无密码」（明文包零额外开销），再按候选顺序逐个试 `-p<password>`，第一个 `returncode==0` 即停。批次内不同包用不同密码时，把密码都列上即可，无需逐包配置。
- **实测 7-Zip 26.02 的失败特征**（这是分类与重试的依据）：
  | 情形 | rc | 输出 |
  | --- | --- | --- |
  | 无密码 / 加密包 | 255 | `Break signaled`（stdin 关闭后无法交互询问密码） |
  | 密码错误 / 普通加密 7z | 2 | `Data Error in encrypted file. Wrong password?` |
  | 密码错误 / 加密文件名的 7z | 2 | `Cannot open encrypted archive. Wrong password?` |
  | 密码错误 / ZIP / 分卷 | 2 | `Wrong password` / `CRC Failed in encrypted file. Wrong password?` |
  | 密码正确 | 0 | 无输出，文件完整 |
  **关键坑**：错密码时 7-Zip 也会写出 0 字节 / 半截文件，所以每次重试前必须 `_clear_staging()` 清空隔离暂存区，只有 rc=0 那次结果才允许 `relocate()` 落地。密码类关键词必须先于 `data error` / `crc` 判断，否则会被误归 corrupt。
- **ZIP 双路径**：`_zip_encryption_info()` 用 `flag_bits & 0x1` 判加密、用 `compress_type == 99` 或 extra 里的 `0x9901` 判 WinZip AES。AES 加密 ZIP 的 Python `zipfile` 会抛 `NotImplementedError("That compression method is not supported")`，必须整包转 7-Zip；ZipCrypto 则由内置 `zf.open(info, pwd=...)` 解密（错密码抛 `RuntimeError("Bad password for file")`），并额外尝试 UTF-8 / GBK 两种密码字节编码。
- **明确原因码**：未提供密码 → `password_required`（明细给出 `--password` / 页面填写指引）；全部候选都错 → `wrong_password`（写明已尝试的候选数）。两者都是包级失败，不影响其它包。`encrypted` 保留为兼容用的通用兜底码。
- **安全边界**：明文只存在于 `PasswordContext` 与本次任务内存，HTTP worker 的 `finally` 用完即清空；不写入 `messages` / `items` / `groups` / 汇总 / 日志 / 响应 / localStorage；汇总只给 `auth{provided,candidates,attempted,solved}` 数量。`scrub()` 只清洗 `-p<密码>` / `password=<密码>` 这类明确回显形态，**刻意不做全局替换**——否则密码恰为 `data`、`src` 时会把 7-Zip 报错中的文件名打碎。
- 前端：密码框 `type=password` + 46px 显示切换、候选密码 / 密码本在高级区、票据式安全约定提示；汇总新增 `AUTH / 密码` 摘要条与 `password_required` / `wrong_password` 的处理建议，均不含明文。设计令牌沿用既有 ink / surface-2，未引入新色值。

## 4. 页面 ↔ 程序参数与返回约定

```
POST /api/jobs  body: {mode,inputDir,archives[],outputDir,overwrite,useArchiveSubdir,
                       externalTool, password, passwords[], passwordFile}
                -> 202 {jobId}   （仅非法 JSON / 字段类型错误返回 400；密码字段类型也在此校验）
GET  /api/jobs/<id> -> {status:"running|done|error", messages:[{level,text,at}], summary, error}
GET  /api/meta      -> {formats[], reasons{}, externalTool, outputDirDefault, auth{...}}
GET  /              -> 前端页面
```

**关键决策**：路径不存在、格式不支持、加密、密码错误、损坏等业务错误**不返回 4xx**，一律进入汇总的 `failed` 分组，保证「不中断整体任务」。前端采用 350ms 轮询 + messages 增量渲染，任务在后台线程执行；密码字段由 worker 的 `finally` 清空，接口从不回显。

## 5. 统一汇总 schema `batch-extract-summary/v1`

```
counts        {success, failed, skipped}  条目级：成功落盘文件 / 失败条目（包级失败记 1）/ 同名跳过
archiveCounts {ok, partial, failed}       包级：无失败 / 有成功也有失败 / 零成功且有失败
groups        {failed:[{reason,label,count,items:[{archive,path,detail}]}], skipped:[...]}
items         [{status,archive,path,reason,detail}]  扁平明细，便于二次处理
volumeSets    [{name,first,last,count,missing:number[]}]  本次识别到的分卷组（含缺卷组）
auth          {provided:bool, candidates:int, attempted:int, solved:int}  密码摘要，无明文
messages      [{level,text,at}]；outputDir；startedAt；finishedAt
```

`volumeSets` 与 `auth` 都是 v1 新增可选字段，其余结构不变；一组成分卷只算 1 个压缩包，计入 `archiveCounts`。`auth.attempted` = 触发过「需要认证」判定的包数（含未提供密码的包），`auth.solved` = 靠某个候选密码成功解压的包数。

`groups.failed` 与 `groups.skipped` 按原因码归类，覆盖全部非成功项；`count` 恒等于 `items.length`。CLI 与 HTTP 返回结构完全同构。

## 6. 原因码

| reason | 含义 |
| --- | --- |
| corrupt | 包/条目损坏、CRC 失败、截断 |
| encrypted | 压缩包或条目已加密（旧通用码，保留兼容） |
| password_required | 已加密但未提供密码，已跳过并提示填写密码 |
| wrong_password | 提供的候选密码全部不正确，已跳过并提示核对 |
| missing_volume | 分卷编号不连续（缺首卷 .001 或中间断号），整组跳过 |
| unsupported | 格式不支持或缺少 7-Zip（含 .001 分卷、AES 加密 ZIP） |
| unsafe_path | 绝对路径 / `..` / 盘符 / 符号链接 / 非法字符 |
| conflict | 目标已存在且 overwrite=false（唯一进入 skipped 的原因） |
| io_error | 权限 / 磁盘 / 路径过长 / 目标同名目录 |
| invalid_input | 配置或输入路径有问题 |
| external_failed | 外部工具执行失败（未匹配更具体原因） |
| empty | 空包（提示级，不计入 failed） |

## 7. 异常分层（每层独立捕获，绝不中断其余包/文件）

A 配置收集 → B 打开包 → C 逐条目解到暂存区 → D 外部工具（含密码重试） → E 搬运落地 → F 顶层兜底 → **G 分卷收集层**（扫描补全 → 连续性检查 → 缺卷直接记包级失败并跳过整组） → **H 密码层**（PasswordContext 收集 / 脱敏 / 计数，worker 结束时清空）。
zip 条目加密检查 `flag_bits & 0x1`；CRC 错误由 `copyfileobj` 读完时抛 `BadZipFile("Bad CRC-32")`（加密条目下归 wrong_password）；7z 按退出码 + 输出文本（Wrong password / Data Error in encrypted file / Unexpected end / Next volume / Break signaled）分类，密码类继续换候选，`Next volume` 归 `missing_volume`。条目级失败还会 `_discard_partial()` 删除已写入 staging 的半截文件。

## 8. 可复用的工程技巧

- **中文 zip 名修复**：未设置 UTF-8 标志位时，zipfile 按 cp437 解码；用 `name.encode("cp437").decode("gbk")` 还原 Windows 下写入的中文名。tar 用 `encoding="utf-8", errors="surrogateescape"` 打开，再对 surrogate 字节尝试 gbk 解码。
- **模拟加密 ZIP 做测试**：无需第三方库，把正常 ZIP 字节中所有 `PK\x03\x04`（局部头 flag 偏移 6）与 `PK\x01\x02`（中央目录 flag 偏移 8）的 general purpose bit 0 置 1，即可让 zipfile 判定为加密条目。
- **路径穿越防护**：统一 `replace("\\","/")` 后拒绝绝对路径、盘符、UNC、`..`、Windows 保留名（CON/PRN/NUL/COM1…）、控制字符与 `<>:"|?*`；tar 额外拒绝 symlink / hardlink / device / FIFO。
- **确定性自测**：`counts` 与 `items` 逐项交叉校验、`groups.count == len(items)`、预置文件内容不变证明未覆盖、异常包之后的包仍有输出证明不中断；对比度用 WCAG 相对亮度公式实算而非目测；内联 JS 用 `node --check` 校验语法。
- **前端异步任务**：`POST` 返回 jobId → 后台线程执行 → `GET` 轮询 messages/summary，避免长请求超时；业务错误不抛 HTTP 4xx，前端永远能拿到结构化汇总。
- **Windows 自定义安装目录的程序探测**：PATH 与 `C:\Program Files` 都找不到时，查卸载注册表 `HKLM/HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall`（含 WOW64 两个视图）的 `DisplayName` 与 `InstallLocation`，可定位装在 `D:\7-Zip` 这类非标准位置的工具。仅用 `winreg`，无需第三方库。
- **分卷不要用「按文件名后缀逐个处理」**：那会把 5 个卷当成 5 个损坏包。正确模型是「收集期归组 → 一组产出一个解压单元（unit）」，单元携带 `path/首卷`、`stem/组名`、`volumes[]`、`volumeSet`、`error`，主循环只遍历单元；这样 `archiveCounts` 也天然按组计数。
- **前端运行时逻辑的无浏览器校验**：当浏览器 DOM 快照为空 / 截图超限时，可在 Node 里 mock 最小 `document`（getElementById 返回带 `innerHTML`/`textContent`/`disabled`/`classList`/`addEventListener` 的对象）、mock `fetch` 走空态分支，把页面 `<script>` 末尾 `})();` 前注入 `globalThis.__renderSummary = renderSummary;` 后 `eval`，再喂入后端真实汇总 JSON，即可验证渲染分支不抛错且产出预期文本。
- **制造真实多卷样例**：用 `7z a -v25k -mx0 <archive> <src>`，`-mx0`（不压缩）+ 随机字节数据才能保证真的切成多卷；可压缩数据即使大也可能只有 1 卷。
- **制造真实加密样例**：`7z a -pSECRET`（普通加密 7z）、`-pSECRET -mhe=on`（连文件名一起加密）、`-pSECRET -mem=ZipCrypto x.zip`、`-pSECRET -mem=AES256 x.zip`（AES ZIP）、`-pSECRET -v25k -mx0`（加密分卷）。Python 标准库无法创建加密 ZIP，必须借 7-Zip 才能覆盖真实链路。
- **密码重试必须清空暂存区**：错密码不会让 7-Zip 干净失败，它会留下 0 字节文件；「每次尝试前 `_clear_staging()` + 只有 rc=0 才允许搬出」是避免把错数据写进用户输出目录的关键。
- **脱敏不要做全局字符串替换**：`text.replace(password, "***")` 在密码恰好是常见词时会破坏错误详情里的路径。只清洗带明确前缀（`-p` / `password=` / `密码:`）的回显形态，配合「代码从不打印命令行」这一根本约束，才兼顾安全与可读性。
- **候选密码覆盖「一批包多个密码」**：把顺序尝试放在单个包的解压循环里（无密码 → 候选 1 → 候选 2 …），比给每个包做密码映射更简洁，且对明文包零开销；`auth{solved,attempted}` 让结果可观测而不泄露明文。
- **前端密码字段**：`type=password` + `autocomplete="new-password"`，显示切换只改 DOM 的 `type`，不复制明文、不写 localStorage；单密码字段不 `.trim()`（首尾空格可能是密码的一部分），按行读取的候选密码才逐行 trim。

## 11. 一键启动：双击 bat → 外部浏览器（Windows 可复用模式）

**分层**：`start.bat` 只做「找 Python + 可编辑配置 + 调用」，所有判定放 `launch.py`。bat 里写复杂判定（延迟变量展开、引号嵌套、errorlevel）极易出错；薄 bat + 厚 Python 更易测、更易改。

| 环节 | 做法 | 踩过的坑 |
| --- | --- | --- |
| 中文编码 | bat 存 **GBK + CRLF**，首行 `chcp 936`；同时 `set "PYTHONIOENCODING=gbk"` | UTF-8 的 bat 在 cmd 里按 936 解析会乱码；Python 输出被管道重定向时默认 UTF-8，与 GBK 控制台不一致，也会乱码 |
| 解释器定位 | `BX_PYTHON` 显式配置 → `where python` 逐个 `--version` 实测 → `where py` 用 `-3 --version` → `%USERPROFILE%\.workbuddy\binaries\python\versions\*` → `%LOCALAPPDATA%\Programs\Python\Python3*` → `C:\Python3*` | `where py` / `where python` 常命中 `AppData\Local\Microsoft\WindowsApps\` 的**商店别名 stub**，必须排除；用纯 bat 变量替换 `%CAND:WindowsApps=%` 判断，别用 `find`（Git Bash 的 Unix `find` 会抢占 PATH） |
| 子过程调用 | `for /f ... do call :TRYP "%%P"`，label 内首行 `if defined PYEXE goto :eof` | 在 `for` 块里直接 `set` + `%VAR%` 读取会被一次性展开，取不到新值；`call :label` 每次重新解析，天然避开延迟展开 |
| 端口复用 | `probe(port)` 先 `GET /api/meta`，校验 `schema == batch-extract-summary/v1` 且 `formats` 是数组；只连端口不算「我们的服务」 | 端口被别的程序占用时不能误连、更不能 `taskkill`；复用已运行服务可避免双击两次起两个进程 |
| 就绪等待 | 启动后轮询 `/api/meta` 最多 15s，同时检查子进程 `poll()` 是否提前退出 | **必须先等就绪再开浏览器**：先开浏览器会停在连接失败页，浏览器不会自动重试 |
| 外部浏览器 | `os.startfile(url)`（Windows ShellExecute → 系统默认浏览器），失败回退 `webbrowser.open(url, new=2)`；仍失败打印 URL | 这打开的是 Chrome/Edge 等**外部浏览器**，不是 IDE 内置预览面板；`BX_BROWSER` / `--browser` 可指定 exe |
| 进程生命周期 | `subprocess.Popen(..., creationflags=DETACHED_PROCESS \| CREATE_NEW_PROCESS_GROUP)`，stdout/stderr 写 `%TEMP%\batch-extractor-server.log` | 服务脱离 bat 控制台，双击后黑窗口自动关闭也不影响页面；日志重定向便于排障，避免控制台一闪而过看不到错误 |
| 安全停止 | `netstat -ano -p TCP` 解析 `LISTENING` 且本地端口匹配的 PID → 再次校验 `/api/meta` 属于本服务 → `taskkill /PID <pid> /F` | 必须同时限定 `LISTENING`（否则会把 ESTABLISHED 客户端算进来）并做 HTTP 校验，避免误杀无关进程 |

**实测（Windows 11）**：`start.bat --status` → `--no-browser` 起服务（PID 30696）→ 再双击（复用同一 PID、不重复启动）→ `os.startfile` 成功在 Edge 打开 `http://127.0.0.1:8765/` → `--stop` 释放端口 → `--status` 显示未运行，全链路 rc=0、中文无乱码。`selftest.py` 另用 mock 覆盖「指定浏览器 / 回退默认浏览器 / 端口被占用拒绝终止」三条分支。

**环境差异（验证时注意）**：WorkBuddy 的命令沙箱会在每条命令结束时回收后代进程，故 bat 启动的 DETACHED 服务无法跨命令存活；真实用户双击 bat 时没有这一层回收，服务会常驻。自动化验证应把「启动→复用→打开→停止」放进同一条命令内，或改用受管后台任务保持服务。

## 12. 完整分发包：可复现打包与脱离原目录验证

**目标**：把「与这个解压程序有关的一切」打成一个可直接分发的 zip，解压后双击 `start.bat` 即用。

| 决策 | 做法与理由 |
| --- | --- |
| 格式与结构 | 选 zip（Windows 原生可读、无需额外工具）；顶层目录固定 `batch-extractor/`，解压即得完整项目文件夹；`ZIP_DEFLATED` 压缩级别 9；zip comment 写明用法与生成时间 |
| 白名单而非黑名单 | `REQUIRED` 显式列出 6 个源码/入口文件 + `samples/input/*` glob。**排除** `__pycache__/`、`*.pyc`、`output/`（运行时解压产物）、归档自身；不用「排除所有 .7z」这类宽规则——样例里就有 `demo_locked.7z` |
| 文档副本 | `--docs 别名=路径` 把已有的架构笔记与工作日志收进 `docs/`，不落地到项目目录；源不存在时跳过并在 MANIFEST 标注，不中断打包 |
| MANIFEST.txt | 每个条目的包内相对路径 / 字节数 / **原始内容 SHA256** / 用途；另写运行方式、依赖、排除项。用 `路径 | 字节 | SHA256 | 用途` 分隔符格式，**不要用 `%-46s` 对齐列**——中文名显示宽度是 2 会导致错位 |
| 中文文件名 | `zipfile` 对非 ASCII 文件名自动置 UTF-8 flag（`0x800`），实测 `docs/架构与工程知识.md` 为 True；Windows 资源管理器可正确显示 |
| 口径一致 | MANIFEST 与控制台输出都标「内容文件总字节（不含本清单）」，避免「含/不含 MANIFEST」两个数打架 |
| 可复现 | 打包脚本自身也进包，解压后运行 `python make_package.py` 即可重新生成；不带 `--docs` 时优雅降级为只打项目本体 |

**验证方式（关键）**：不能只检查 zip 能打开，必须**解压到全新临时目录后从副本实跑**，才能证明路径无关、依赖齐全：
1. 按 MANIFEST 逐文件核对大小与 SHA256（本次 15 个内容文件，零差异）；
2. 副本运行 `python selftest.py` → 135/135；
3. 副本运行 `cmd.exe /c start.bat --status --port <空闲端口>` → rc=0、中文无乱码（证明 `%~dp0` 定位有效）；
4. 副本运行 `python make_package.py` → 重新生成 14 条目 zip（无 docs 时正确跳过），CRC 全通过。

**本次产物**：`batch-extractor-2026-11-14.zip` 位于工作区根目录，16 个条目（15 内容 + MANIFEST），内容文件约 320 KB。包内含 6 个源码/入口文件、7 个试用样例、2 份文档副本与清单。包自身 SHA256 由打包脚本在生成时打印、在交付回复里给出；**刻意不写进会收录进包的文档**，否则形成「记录哈希 → 文档变化 → 包哈希变化 → 记录过时」的循环。包内 MANIFEST 的逐文件 SHA256 才是稳定可自校验的依据；文档副本为打包时刻快照。

**通用经验**：分发包的价值不在「文件都在」，而在「解压后不依赖原工作区也能跑」。把哈希清单、白名单排除规则、以及「从副本实跑」写进打包脚本，可以把一次性手工压缩变成可复现的交付流程。
