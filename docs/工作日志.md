## 批量解压程序 + 配套前端页面（batch-extractor/）
- 交付物：`batch_extract.py`（核心库 + CLI + 本地 HTTP 服务，零第三方依赖、Python 3.8+）、`web/index.html`（单文件前端）、`selftest.py`（56 项确定性断言）、`samples/`（试用样例）。
- 关键技术决策：两阶段 `staging → relocate`，让所有格式共用同一套冲突检测 / 覆盖策略 / 路径安全 / 统计；默认不覆盖，同名记 `skipped/conflict`；异常分 6 层独立捕获，逐包逐条目不中断；CLI 的 stdout 恒为同一份汇总 JSON，提示走 stderr，业务失败不返回 4xx。
- 汇总 schema `batch-extract-summary/v1`：`counts{success,failed,skipped}` / `archiveCounts{ok,partial,failed}` / `groups.failed|skipped`（按 reason 归类）/ `items` / `messages`。原因码：corrupt、encrypted、unsupported、unsafe_path、conflict、io_error、invalid_input、external_failed。
- 前端设计定调：Industrial / utilitarian 工业实用·工单票据风；暖纸白 + 深墨 + 信号橙；展示字 Archivo Black / Noto Sans SC 900，数据 IBM Plex Mono；37/63 非对称双栏、4 组 80ms 错峰入场、reduced-motion 降级。

- 验证：`selftest.py` 56/56 通过（含真实 .7z 创建与解压、CLI、HTTP、前端静态 QA 与 WCAG 对比度实算）；内置浏览器端到端跑通「配置 → 启动 → 提示流 → 计数条 → 按原因码分组汇总」，样例结果为成功 1 / 失败 1 / 跳过 1（预置同名文件未被覆盖）。
- 运行：`python batch_extract.py --serve --port 8765` → http://127.0.0.1:8765。

## 追加需求：加密压缩包输密码解压（同日）
- 用户说明实际压缩包带密码。新增 `PasswordContext`（`password` / `passwords[]` / `passwordFile` / 环境变量 `BX_PASSWORD`、`BX_PASSWORD_FILE`，去重保序、上限 200），每个包先试无密码再按候选顺序试 7-Zip `-p`，成功即停；批次内不同包不同密码也能一次跑完。
- 实测 7-Zip 26.02：无密码加密包 rc=255 `Break signaled`；错密码 rc=2 `Wrong password` / `Data Error in encrypted file. Wrong password?` / `Cannot open encrypted archive. Wrong password?` / `CRC Failed in encrypted file. Wrong password?`；**错密码也会写出半成品文件**，故每次重试前清空 staging，只有 rc=0 的结果才落地。
- 加密 ZIP 双路径：`flag_bits&0x1` 判加密、`compress_type==99` 或 extra `0x9901` 判 AES；AES ZIP 整包转 7-Zip（zipfile 会抛 NotImplementedError），ZipCrypto 用内置 `zf.open(pwd=...)` 并试 UTF-8/GBK 两种字节编码。
- 新增原因码 `password_required`（未提供密码）/ `wrong_password`（候选全错），`encrypted` 保留兼容；汇总新增可选字段 `auth{provided,candidates,attempted,solved}`，只给数量不给明文。
- 安全约定：密码仅在任务内存，HTTP worker `finally` 清空；不写入汇总/messages/日志/响应/localStorage；`scrub()` 只清洗 `-p<密码>` 等明确回显，避免全局替换打碎报错里的文件名。
- 前端：密码输入框 + 显示切换、候选密码/密码本在高级区、票据式安全提示、汇总区 `AUTH / 密码` 摘要与密码问题处理建议；设计令牌不变（新增色对 ink/#e8e4da 实测 13.38:1）。
- 样例：`samples/input/demo_locked.7z`，密码 `demo123`，内含中文路径文件。
- 验证：`selftest.py` 122/122 通过；CLI 与页面接口端到端（带密码）跑通，4 卷仍归 1 组、加密包正确解出、响应无明文；Node 最小 DOM 前端运行时校验 10/10；服务已用新代码在 8765 重启并验证。

## 追加需求：双击 bat 一键起服务并在外部浏览器打开页面（同日）
- 新增 `start.bat`（GBK + CRLF、`chcp 936`、`PYTHONIOENCODING=gbk`、可编辑 `PORT` / `BX_BROWSER` / `KEEP_CONSOLE` / `BX_PYTHON`）与 `launch.py`（启动器）。bat 只负责定位 Python 与传参，判定逻辑全在 Python 里。
- 解释器定位顺序：显式 `BX_PYTHON` → `where python` 逐个 `--version` 实跑 → `where py -3 --version` → WorkBuddy 内置 Python / `%LOCALAPPDATA%\Programs\Python\Python3*` / `C:\Python3*`。跳过 `WindowsApps` 商店别名；用纯 bat 变量替换而非 `find`（Git Bash 的 Unix find 会抢 PATH）；`for /f ... call :label` 规避延迟展开。
- 启动器：`GET /api/meta` 校验 schema 判断「端口上是不是本服务」→ 已运行则复用不重复起 → 否则用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` 起后台服务、日志写 `%TEMP%\batch-extractor-server.log` → 轮询就绪后才 `os.startfile(url)` 打开系统默认外部浏览器（失败回退 `webbrowser.open`，再失败打印 URL）。
- `--stop`：`netstat -ano` 解析 LISTENING PID + 二次 HTTP 校验后 `taskkill /PID <pid> /F`，端口被其它程序占用时拒绝终止任何进程。另有 `--status` / `--no-browser` / `--port` / `--browser`。
- 实测全链路 rc=0：状态 → 起服务 → 复用同一 PID → Edge 打开页面 → 停止释放 → 未运行；中文输出无乱码。过程中按实测修正两处：Git Bash 环境下 `find` 被抢占、Python 输出重定向时编码与 GBK 控制台不一致。
- 验证：`selftest.py` 135/135 通过（新增 13 项启动器断言，含 mock 覆盖浏览器分支与安全停止）；服务已恢复在 8765，页面 200。
- 环境事实补充：WorkBuddy 命令沙箱会在每条命令结束时回收后代进程，bat 的 DETACHED 服务无法跨命令存活；真实双击场景不受影响，自动化验证需把整条链路放进同一命令或用受管后台任务。
